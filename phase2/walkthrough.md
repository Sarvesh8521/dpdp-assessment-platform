# Walkthrough: Phase 2 Reconciliation Engine Fixes

## Changes Made

### 1. Re-aligned with the Phase 2 Specification
- **Removed the 8th Rule**: Removed the undocumented `GTMCMPConfigReconciliation` rule from the engine (including its invocation and unit test `test_recon_gtm_cmp_config.py`).
- Maintained exactly the 7 required reconciliation rules as defined in PHASE2_SPEC Section 5:
  1. GTM vs Phase 1 tags
  2. GTM consent settings vs Phase 1 consent signals
  3. GA4 linked services vs declared scope
  4. Google Ads Customer Match vs CMP purposes
  5. GitHub SDKs vs declared marketing platforms
  6. Search Console properties vs declared properties
  7. CMP purposes vs GTM tag categories

### 2. Standardized Outcomes & Confidences
- **Missing Source**: Re-wired every reconciliation rule to guarantee that if a required source is missing, the engine emits `insufficient_data` instead of incorrectly flagging it as a `contradiction`.
  - Added explicit test coverage for missing sources across all rules.
  - Set `human_review_required=False` for missing source (`insufficient_data`) conditions.
  - Asserted `confidence=Confidence.LOW` across missing source validations.
- **Agreement**: Re-verified that agreeing sources generate `Confidence.HIGH`.
- **Contradiction**: Set `human_review_required=True` across the board for explicitly proven discrepancies (`contradictions`).
- **Verdicts Validation**: Checked that `LOW` confidence can never generate `Not observed` (handled safely by `EvidenceItem.validate_confidence_verdict_rules`).

### 3. Source Identities and Traceability
- Evidence IDs from Phase 2 findings are correctly resolved. The string representations (`e.source`) are mapped inside `run_reconciliation`'s wrapper within `AssessmentService` to explicitly link directly to the internal DB UUIDs.
- Ensured both source labels and descriptions (`evidence_a_detail`, `evidence_b_detail`, etc.) populate reliably to provide traceability into the reasoning behind `contradiction` findings.

## Validation Results
- The test suite for reconciliation (`tests/unit/test_recon_*.py`) was executed, reporting `30 passed` checks.
- Confirmed full coverage for **Agreement**, **Contradiction**, and **Missing Source** variants inside every rule plugin.

## Phase 2 Declared Scope Handling Fix

### Changes Made
- **Removed Scope Mutation**: I removed the logic inside `app/services/assessment_service.py` that incorrectly unioned runtime configurations (e.g., `data.config.integrations`, `data.config.properties`, etc.) with `data.config.scope`. This ensures that Phase 2's `scope_sheet` evidence remains completely untainted by runtime discovery.
- **Data Integrity**: Empty or unspecified declared scope lists correctly generate missing sources (`insufficient_data`) for their respective reconciliation rules, preventing false agreements generated by injecting discovered endpoints into the `scope`.
- **Validation Added**: Authored a new test module (`tests/unit/test_declared_scope_handling.py`) proving that even if multiple integrations (`ga4`, `github`, etc.) and domains are configured at runtime, they never automatically leak into the strictly declared `scope_sheet` properties and platforms lists.
